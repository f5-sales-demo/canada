Use Terraform 1.16.3 and the signed xcsh 13.0.3 provider with API 10.0.0,
contract 7.0.0 and telemetry v2. Verify the published artifact before initializing.

Accept the Azure Customer Edge Marketplace terms once at subscription scope.
MCN retains ownership of that shared prerequisite; Canada Topology does not
duplicate it in its state.

Use the local Terraform backend on the Ubuntu deployment workstation. Keep the
state and backups outside the checkout in a directory with mode 0700, and keep
the backend configuration at mode 0600. It contains only an absolute path to the
independent Canada Topology state file. Local state contains credentials, so use
the workstation's protected storage and private backup process.

Azure deployment uses the existing local Azure CLI login. No new Blob data role,
storage key or cloud credential is required. The lifecycle holds an exclusive
operator lock and Terraform locks the local state.

Keep backend configuration, credentials and allocation identifiers
outside Git. Initialize the demo with the private backend configuration and
`-lockfile=readonly`. Set `source_repository` to `f5-sales-demo/canada`,
`source_ref` to `refs/heads/main`, and `source_commit_sha` to the exact clean
merged commit. Supply non-personal owner and actor identifiers.

The demo owns the `canada` application namespace and its dedicated
registration token. CE sites remain in `system`. The existing reserved public-IP
allocation stays in its platform namespace; only its selector binding is managed.

Apply the bootstrap phase, wait for all three CE registrations, then plan and
apply `azure_site_configuration_phase=configured` to bind observed NIC MACs and
approve registrations. Always save and review the full plan before applying it.
Canadian resources must remain in Canada Central or Canada East. Bastion is opt-in.

The public hostname must be exactly `canada.f5-sales-demo.ca`, published through
existing tenant-managed `.ca` DNS to the retained allocation. Remove the former
public hostname only after the exact hostname resolves and Canadian requests pass.
Keep public IPv6 unpublished. Public advertisement has only the reserved RE VIP;
CE BGP, primary-IP and ILB listeners use `internal.canada.f5-sales-demo.ca`, with
no public advertisement or managed public DNS.

The public load balancer explicitly selects the owned service policy with
`allow_list.country_list = ["COUNTRY_CA"]` and `default_action_deny = {}`.
Do not add IP, ASN, workstation, probe, unknown-country or inherited-policy
exceptions. Keep `disable_trust_client_ip_headers` enabled.

Save a refresh-enabled plan and review it with `scripts/plan_scope.py --mode
application`. Application and policy changes and provenance updates are allowed;
CE, origin, FRR, Route Server and reserved-allocation replacement are rejected.
Keep the existing Canada Central deployment; Canada East remains an allowed
placement, and cross-region CE distribution is outside this change.

## Verify the release and initialize

The pinned pair is [signed xcsh v13.0.3](https://github.com/f5-sales-demo/terraform-provider-xcsh/releases/tag/v13.0.3) and [API
v10.0.0](https://github.com/f5-sales-demo/api-specs-enriched/releases/tag/v10.0.0). The verifier checks source identity, ZIP digest,
signature, and embedded API receipt before initialization. Preserve the committed lockfile.

Set `CANADA_PRIVATE` to a protected directory outside the checkout. Keep `canada.tfvars` and `backend.hcl` at mode 0600 and the state directory at mode 0700. The backend file must contain only an absolute `path` to the independent state file. Supply private XC credentials through the existing operator environment and Azure CLI login.

```bash
python3 scripts/verify-showcase-provider.py --private-root "$CANADA_PRIVATE/provider"
terraform -chdir=terraform init -input=false -lockfile=readonly -reconfigure \
  -backend-config="$CANADA_PRIVATE/backend.hcl"
```

Run from a clean checkout equal to the remote merged main. `lifecycle.py` checks exact source, private-input permissions, provider identity,
saved-plan scope and digest, and holds the exclusive operator lock. Its build mode applies bootstrap, polls registration, then applies
configured MAC binding and verifies routing, public traffic, failure/recovery, and zero-change readiness. Its scope validator is an
automated plan review; operators should inspect the saved plans and private logs as well.

```bash
python3 scripts/lifecycle.py --mode build \
  --tfvars "$CANADA_PRIVATE/canada.tfvars" \
  --backend-config "$CANADA_PRIVATE/backend.hcl" \
  --private-root "$CANADA_PRIVATE/build-receipts"
```

## Private client and console access

Read `ca_resource_group_name`, `ca_client_vm_name`, `canada_client_nic_name`, `canada_ilb_console_ip`, and `ca_xc_site_names` from the
independent Terraform state. `ca_site_console_admin_passwords` is sensitive; retrieve it only in the protected operator session. The
lifecycle routing check uses `--skip-console`, so console login needs separate acceptance.

When Bastion is absent, Azure Run Command on the owned Canadian client can test the private console listener without adding public management ingress:

```bash
CANADA_RG=$(terraform -chdir=terraform output -raw ca_resource_group_name)
CANADA_CLIENT=$(terraform -chdir=terraform output -raw ca_client_vm_name)
CANADA_CONSOLE=$(terraform -chdir=terraform output -raw canada_ilb_console_ip)
az vm run-command invoke --resource-group "$CANADA_RG" --name "$CANADA_CLIENT" \
  --command-id RunShellScript \
  --scripts "timeout 10 bash -c '</dev/tcp/$CANADA_CONSOLE/65500'"
```

This checks TCP reachability. Use the supported Site Console at port 65500 through the owned client's approved private access path to verify credentials and health. Do not treat a listening port as a successful console login. Bastion is optional; its absence does not justify opening origin SSH or public console ingress.
