Require three ONLINE CEs, six CE-to-FRR sessions and four FRR-to-Route-Server
sessions. The client effective-route table must show both FRR next hops for the
application VIP. Verify Site Console health and valid credentials.

Collect 120 successful exact-origin samples on each VIP and ILB application path.
Compare every body with the Canadian origin control response. Public traffic must
use the reserved allocation, Toronto/Montreal selector and Canadian CE origin pool.

Run `scripts/verify-canadian-public-re.py` with the deployed Terraform directory,
a new private evidence directory and `--samples 120`. It validates selector,
pool, binding, regional response headers and the exact Canadian origin marker.

Origin ingress must equal the union of all provider-published Regional Edge/CDN
CIDRs, both workstation /32s and exact owned Canadian probe addresses. Reject
unlisted ingress. Origin SSH remains disabled. This infrastructure-source allowlist protects
origin ingress; it is separate from public client country authorization.

Finish with a refresh-enabled plan returning exit code zero, no resource actions
and no output changes. Keep raw evidence private; publish only sanitized receipts.

Public acceptance requires DNS for `canada.f5-sales-demo.ca` to resolve to the
retained allocation, 120 successful Canadian-source requests, both exact RE
selectees (`tr2-tor` and `mtl7-mon`), and the exact Canadian origin response.
Denied non-Canadian requests must include spoofed `X-Forwarded-For`, `Forwarded`
and `X-Real-IP` headers. Bind each negative receipt to its observed egress IP
and the XC country classification of that actual source. An Azure region alone
is not classification evidence. Unknown countries must remain denied.

Audit source, rendered pages, machine-readable endpoints, state and live XC
objects together. Unavailable live reads or stale rendered documentation fail
acceptance. Repeat public and internal traffic checks during independent CE and
FRR failures and after recovery. Publish only sanitized audit and acceptance
receipts; retain observed source addresses and raw XC events in private evidence.

Use `scripts/verify-country-receipts.py` to validate private classification and
negative-test receipts. It rejects receipts without matching observed egress,
XC source addresses, country classification and explicit policy-denial evidence
for every plain and spoofed forwarding-header variant.

## Run the supplied gates

The following commands consume protected state or receipts. Keep their evidence directories outside Git and sanitize results before sharing.

```bash
python3 scripts/verify-canadian-public-re.py --terraform-dir terraform \
  --evidence-dir "$CANADA_PRIVATE/public-receipts" --samples 120
python3 scripts/verify-country-receipts.py "$CANADA_PRIVATE/country-receipt.json"
python3 scripts/lifecycle.py --mode verify \
  --tfvars "$CANADA_PRIVATE/canada.tfvars" \
  --backend-config "$CANADA_PRIVATE/backend.hcl" \
  --private-root "$CANADA_PRIVATE/verify-receipts"
```

The public RE verifier validates configuration and exact-origin responses; the country-receipt validator separately requires observed
egress, matched XC source/classification, 120 Canadian successes, and explicit policy-denial evidence for every negative header variant.
Prepare that private JSON receipt from actual events; do not infer classification from location.
